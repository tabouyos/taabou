# 健診センター予約・通過管理システム

健診センター（人間ドック・健診施設）向けの予約管理 Web アプリ。
単一 HTML ファイル（HTML + CSS + JavaScript）＋ Supabase（バックエンド）で動作します。フレームワーク・ビルド不要。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `kenshin-v17.html` | 本体（これを開けば動く。正＝カノニカル）。v17で職員ログインを追加 |
| `kenshin-v17_RLS_職員ログイン限定.sql` | データを「ログインした職員だけ」に限定するSQL（全PCをv17にしてから実行） |
| `kenshin-v17_RLS_元に戻す.sql` | 上の制限を元に戻す緊急用SQL |
| `kenshin-v17_職員アカウント一括作成.sql` | 職員番号・氏名の一覧から、共通の仮パスワードで職員アカウントをまとめて作るSQL（既存は飛ばす） |
| `kenshin-v17_職員パスワード再設定.sql` | 職員のパスワードを再設定するSQL |
| `kenshin-v17_職員パスワード未変更の確認.sql` | まだ初回ログイン（仮パスワードのまま）の職員を一覧するSQL |
| `職員アカウント登録票.pdf` | 職員に職員番号・氏名を書いてもらう登録用紙（A4・40名分） |
| `職員アカウント登録票.xlsx` | 同じ登録票のExcel版。「SQL貼り付け用」シートに一括作成SQLへ貼る行が自動で作られる |
| `kenshin-migration-add-columns.sql` | Supabase 追加マイグレーション（列追加＋同期用テーブル） |
| `健診センターシステム_使用書.html` | スタッフ向け使用書（印刷・PDF配布用） |
| `README.md` | このファイル |

## 使い方（ローカル）

`kenshin-v17.html` をブラウザ（Chrome / Edge 推奨）で開き、職員番号とパスワードでログインする。アカウントは管理者が Supabase の管理画面（Authentication → Users）で発行する（職員番号 12345 → `12345@staff.kenshin.invalid`）。

## Supabase（バックエンド）

- プロジェクト：既存の Supabase プロジェクトに接続（接続情報は HTML 内に記載）。
- スキーマ更新：Supabase > SQL Editor で `kenshin-migration-add-columns.sql` を実行すると、
  最新機能（事前問診の発送状況・初回/リピーター・通過管理のメモ/臥床・お休み医師・カルテ準備・当日キャンセル/追加）が全 PC で同期されます。冪等なので何度流しても安全。
- 接続できない場合も、各端末内（localStorage）で動作します。

## デプロイ（Netlify 予定）

- 静的ファイルのみなので、Netlify にドラッグ&ドロップ、または GitHub 連携で公開可能。
- 公開 URL を各 PC のブックマークにすれば、HTML の手配布が不要になります。

## 開発メモ（このプロジェクトの流儀）

- 単一ファイルを維持（分割は任意）。
- 編集は外科的（必要箇所のみ）に行う。
- テンプレートリテラルは使わず、シングルクォート＋文字列連結で統一。
- 変更のたびに、`<script>` ブロックを取り出して構文検証：
  ```bash
  node --check <抽出したJS>
  ```
- Codex 等の外部生成物は「検証用途のみ」。正はこのリポジトリの `kenshin-v17.html`。

## 注意

- Supabase の anon キーが HTML に含まれますが、RLS（行レベルセキュリティ）を有効にしてある前提の公開設計です。念のためリポジトリは **Private** を推奨します。
